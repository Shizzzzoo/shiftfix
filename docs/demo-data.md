# Fictional factory dataset

Dataset `shiftfix-history-v1` was additively imported into the ShiftFix live table on 2026-11-14. It spans 2026-09-14 through 2026-11-14 and contains 177 fictional work orders across 62 dates, including 128 completed,16 rejected,7 skipped,3 merged,10 pending review,2 needing details,4 open,4 in progress and 3 awaiting verification. Twelve of these work orders are archived.

The connected records include 11 assets (one retired),4 asset types,4 categories,3 locations,6 zones,6 sub-zones,3 teams,4 vendors,4 part types,3 stores locations,8 parts,12 purchase records,4 inspection templates,28 responses,6 meters with 54 readings,6 preventive plans,3 threshold rules and 6 part-life records. Part quantities reconcile to their opening balances, receipts and issues. Work-order events retain dated fictional actor names, and merged reports link to actual same-asset demo requests. An existing licensed factory photograph in private S 3 is explicitly labeled illustrative demo photography; it is not proof of actual repairs.

Every seeded record is tagged `demoSeed=shiftfix-history-v1`, with stable deterministic keys. Work orders use `DEMO-` numbers; catalogs and people carry visible Demo labels. The application displays the date range and fictional-data notice on every page. The 8 demo people are display-only DynamoDB records, not Cognito identities; they cannot sign in, receive new live assignments or change access roles. Actual users and access permissions are preserved. Team membership remains descriptive metadata only.

All 6 demo plans and 3 rules start paused. Upcoming lists paused schedules as previews. The import contains no TIMER# outbox records, so historical deadlines do not launch workflows. Billing remains real application usage counts and an AWS console link; no fictional bills or transactions with suppliers are sent.

`scripts/build-demo-data.py` builds the deterministic local dataset and an encoded private import artifact in `.deploy/`. `scripts/import-demo-mcp.py` is a run_script snippet for the official AWS MCP service: it discovers the table from the completed stack, reads every target key, inserts only absent tagged records with conditional transactions and a shared catalog revision guard, and writes the completed manifest last. It never overwrites existing records. A completed replay exits without writes. Do not overwrite the original private import artifact to change dates; use a deliberately versioned future dataset if another history is requested.

Verified live through the IAM-authorized API: all 18 catalog kinds populated,177 demo work orders covering the requested range,12 archived, and zero enabled demo plans or rules. Local populated-state browser checks exercised every catalog and specialized section, work-order activity, stock and meter histories, paused schedules and read-only people. Axe scans found zero violations in tested populated overview, Upcoming, Users and mobile overview states; longer chart lists were made keyboard focusable after a populated-state check exposed the issue. Backend suite 92 tests passes. Full human multi-user browser flow remains a separate check.

The dataset is intentionally useful for demos and exports. Its records contribute to the dashboard counts; they must be identified as fictional in hackathon write-ups and recordings. Preserve real records if removing demo data later; removal was not performed as part of this import.
