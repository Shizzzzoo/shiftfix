# ShiftFix operations expansion
User supplied screenshots of a broad CMMS and requested as many functional modules as practical. Preserve original brand, private evidence, role hierarchy, onboarding and reviewed transitions. Do not copy reference metrics or imply fake IoT telemetry.

## Deliverable scope
Operations overview with real scoped filters and live-derived counts, completion donut and breakdowns by owner/asset/location. Full sidebar hierarchy for requests, existing work orders, upcoming/recurrent plans, asset monitoring, inspections templates/responses, meter definitions/readings, inventory/vendors/part types/part locations/stock movements/life tracking/purchase orders, categories, asset registry/types, locations/zones/subzones, teams/users, download centre and recoverable archive. Single factory remains; no misleading multi-factory selector. Real AWS spending not invented: Billing/usage page links AWS console for admin and labels app counts as usage, no subscription/payments.

## Backend
Single DynamoDB catalog partition family, typed schema allowlists, optimistic versions, archive/restore no hard deletion. List all pages. Managers/admin manage master data, workers may record permitted meter readings and inspection responses; reporter sees only necessary machine/category/location master data. Preserve parent references, validate asset and hierarchy cross references. Dynamic /machines merges legacy defaults and saved assets; new work orders snapshot asset metadata. Dedicated stock movements atomically change quantities and prevent negative stock; receiving purchase order once updates stock transactionally. Append audits. Purchasing means internal PO records, never actual money transfers/orders to third parties.
Preventive plans every N days, future/UTC next run, enabled pause/resume, hourly EventBridge rule invokes scheduler. Conditional deterministic occurrence idempotency and bounded catchup, no duplicate jobs under concurrency. Creates pending review requests with reference to plan, no automatic repair closure. Workflow SLA settings persisted; future work-order transitions use them. Automations initially explicit meter-threshold fault creation with enabled rules, no fake external notification. Add counters/records for manual readings; clearly label manual monitoring.

## Frontend
Data-driven typed catalog screens with search, add/edit, inline form validation, related entity dropdowns, archive/restore, CSV export. Specialized inventory adjust/PO receive, inspection template prompts and response forms, meter readings, recurrence editor, SLA form, archived work order restore. Download centre CSV exports and CSV template/import for assets limited100rows/1MB; spreadsheet-friendly CSV with formula injection escaping. Bulk archive requires preview + explicit confirmation and cannot archive unresolved work orders. Global filters for status/date/asset/category/team/owner/location/zone/subzone use authorized actual fields; unsupported/empty attributes never fabricate data. No dead menus or hardcoded thousands of workorders. Charts have textual equivalents, proper labels, keyboard support and mobile layout. Existing photos retained.

## Verification
Backend regression tests including privileges, foreign references, stale versions, negative stock, duplicate receiving, scheduler idempotency, CSV limits. UI smoke CRUD, filters, inspection form, report oversize protections, desktop/mobile + axe. CloudFormation updates only scoped new schedule/Lambda resources, no deletion of retained production state. Deploy immutable package, wait complete and verify runtime.

## Rulings
Billing is operational usage and an AWS console link, not invented subscription billing. Excel Delete becomes previewed bulk archive because permanent deletion conflicts with audit/history safety. Manual monitoring is not represented as connected IoT. Team membership organizes records but does not confer authorization roles.
